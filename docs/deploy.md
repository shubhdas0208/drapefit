# Deploy runbook (₹0): Telegram + Render free + Neon free + cron-job.org

These steps need your own accounts, so they can't be automated from here. Total time is about 30 minutes.

## 0. Try it on your laptop first (5 min, no accounts except BotFather)

1. In Telegram, open **@BotFather**, send `/newbot`, pick a name (e.g. DrapeFit) and a username ending in `bot`. Copy the token.
2. In PowerShell: `setx TELEGRAM_BOT_TOKEN "<token>"`. Then open a **new** terminal.
3. `cd "<your DrapeFit folder>"` and run `.venv\Scripts\python scripts\run_local.py`
4. Message your bot. It works while the laptop is awake. Links open stores directly in this mode, so clicks are not tracked. State goes to `drapefit-local.db`.
5. To see the "did you buy?" message without waiting 24 h: `setx FOLLOWUP_DELAY_MINUTES 2`, open a new terminal, restart `run_local.py`, add something to the cart and send `checkout`. The local script checks for due follow-ups every minute. Set it back with `setx FOLLOWUP_DELAY_MINUTES 1440`.

## 1. Neon (database)

1. Sign up at neon.tech (free plan), create project `drapefit`, region **AWS ap-southeast-1 (Singapore)** to sit near Render Singapore.
2. Copy the connection string (`postgresql://...neon.tech/neondb?sslmode=require...`). The app converts it for asyncpg itself, and creates its tables on first boot.

## 2. Code on GitHub (Render deploys from a repo)

```
cd "<your DrapeFit folder>"
git init -b main
git add .
git commit -m "feat: DrapeFit Rung 1 telegram bot"
gh repo create drapefit --private --source . --push
```
`.gitignore` already excludes `.env`, `.venv/` and `*.db`. Check `git status` before the commit anyway.

## 3. Render (web service)

1. render.com → New → **Blueprint** → pick the `drapefit` repo. It reads `render.yaml` (free plan, Singapore, `/healthz` health check).
2. Fill in the secret env vars when prompted:
   - `TELEGRAM_BOT_TOKEN`, `SARVAM_API_KEY`, `SHOPIFY_CLIENT_ID`, `SHOPIFY_CLIENT_SECRET`: your values
   - `DATABASE_URL`: the Neon string
   - `PUBLIC_BASE_URL`: optional. The app falls back to Render's own URL (`RENDER_EXTERNAL_URL`). Set it to `https://<service-name>.onrender.com` to make it explicit.
   - `AGENT_PROFILE_URL`: leave empty for now (T9)
   - `TELEGRAM_WEBHOOK_SECRET` and `TASKS_SECRET` are generated by Render. Copy both values from the dashboard.
3. Wait for "Live", then open `https://<service>.onrender.com/healthz` → `{"ok":true}`.

## 4. Point Telegram at Render

The script sends Telegram a SHA-256 fingerprint of `TELEGRAM_WEBHOOK_SECRET` (Telegram rejects some characters in Render's generated value); the server checks the same fingerprint.

```
setx TELEGRAM_WEBHOOK_SECRET "<value from Render>"
(new terminal)
.venv\Scripts\python scripts\set_webhook.py https://<service>.onrender.com
```
Running `run_local.py` later removes the webhook. Re-run this step afterwards. (Re-running it is also required once after Rung 2, so Telegram starts sending button taps.)

## 5. cron-job.org (keeps Render awake + daily cleanup)

1. Job 1: `GET https://<service>.onrender.com/healthz` every **10 minutes**. Turn on failure email alerts.
2. Job 2: `POST https://<service>.onrender.com/tasks/followups` **every hour**, header `X-Tasks-Secret: <TASKS_SECRET>`. It sends due "did you buy?" messages and deletes data older than 90 days.

## 6. Check it end to end

- Send the bot: `grey turtleneck M and blue bell-bottoms waist 32, men, under 2000 each`
- Expect "Searching 2 items…" within about 1 s, then two albums and lists (A1-A5, B1-B5) within about 6-8 s.
- Tap **+** under A1 and B1, then **Checkout**. Expect one "Pay on <brand>" button per brand, each opening that brand's checkout with the items in it.
- Tap an **open** link. In the Neon SQL editor, check the event:
  `select type, payload, ts from events order by id desc limit 20;` should show `link_clicked`.

## Free-tier limits to watch

| Service | Limit | What happens |
|---|---|---|
| Render free | 750 instance-hours/month; may restart at any time | One always-on service fits. A restart mid-search loses that request (event log shows `request_received` with no `results_shown`). |
| Neon free | 0.5 GB; compute sleeps when idle | ~1 s extra on the first query after idle |
| Shopify catalog | 5 req/s per client | Two users searching at once each get slower replies (~8-10 s) |
| Sarvam | your credit balance | `parsed` events record the model and latency. sarvam-105b-conversations uses ~300 output tokens per parse. |
